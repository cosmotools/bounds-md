# bounds — плагин Claude Code для BOUNDS.md

`BOUNDS.md` — это рамки проекта, которые пишут люди. Ставишь плагин, кладёшь `BOUNDS.md` в корень проекта, и всё работает сразу. Ни правки CLAUDE.md, ни ручных настроек не нужно.

## Установка

```
/plugin marketplace add <путь к этой папке или github-репозиторий>
/plugin install bounds@bounds-md
```

Потом в проекте выполнить `/bounds:init` или просто создать `BOUNDS.md` руками.

## Что делает плагин

| Когда | Что происходит |
|---|---|
| Старт сессии | Ищет `BOUNDS.md` в корне проекта и передаёт его Claude с правилами, как его соблюдать. В чате появляется строка вида `BOUNDS.md: 7 rule(s) in 4 section(s)`. |
| Файл новый или изменился | В следующем ответе Claude делает короткую проверку: размытые формулировки, конфликты, описания вместо ограничений, нарушения в существующем коде. Для каждой проблемы предлагает готовую строку на замену. |
| Файл поменяли посреди сессии | При следующем сообщении Claude получает новую версию и проверяет её. |
| Claude пытается изменить BOUNDS.md | Блокируется: и инструментами Edit/Write, и через терминал (`sed -i`, `>>`, `tee`, `rm`, `mv`…). Создавать файл с нуля можно. |
| Файла нет | Один раз на проект подсказывает про `/bounds:init`. |

Команды:
- `/bounds:init` создаёт `BOUNDS.md` из шаблона и предлагает в чате примеры правил под проект.
- `/bounds:review` делает подробную проверку: формат, проверяемость, конфликты, сверку с кодом, лишнее и пробелы.

Жёстких лимитов нет. Если правил много или они слабые, Claude порекомендует, что объединить или убрать.

## Формат

```markdown
## UI
owner: @anna
scope: src/ui/**
- UI-1 MUST build screens only from components in src/ui/kit — one design system
- UI-2 NEVER add CSS frameworks or UI libraries — styling lives in the kit
```

- **Уровни**: `NEVER`, `MUST` и `MUST NOT` — жёсткие: Claude останавливается, называет ID правила и предлагает варианты. `SHOULD` и `SHOULD NOT` — по умолчанию: Claude может отступить, если объяснит почему.
- **Правило**: одна строка в формате `ID УРОВЕНЬ текст — зачем`. ID — это префикс раздела и номер.
- **Раздел**: `owner:` — кто решает по разделу, `scope:` — к каким путям он относится.
- **Комментарии** `<!-- -->` предназначены для людей, Claude их не принимает за правила.

## Как устроено

```
.claude-plugin/plugin.json        манифест
.claude-plugin/marketplace.json   чтобы ставить через /plugin
hooks/hooks.json                  SessionStart, UserPromptSubmit, PreToolUse
scripts/bounds.mjs                 обработчики хуков
scripts/lib.mjs                   разбор, проверки, защита, состояние
skills/init/SKILL.md              /bounds:init (шаблон внутри)
skills/review/SKILL.md            /bounds:review
test/bounds.test.mjs               npm test
```

Зависимостей нет, нужен только Node. Состояние (какую версию файла уже проверяли) хранится вне проекта: в `$CLAUDE_PLUGIN_DATA`, а если её нет, то в `~/.cache/bounds-md/`.

## Ограничения

- Плагин защищает файл только от Claude. Люди и другие инструменты правят его как обычно.
- Защита в терминале работает по списку разрешённых команд. Команды, которые упоминают BOUNDS.md и не входят в список чтения (например, `cp BOUNDS.md backup.md`), тоже блокируются. Это сделано намеренно, лучше перестраховаться.
- Насколько Claude соблюдает правила, зависит от модели. На чётких NEVER/MUST в тестах он останавливался надёжно, но смысловая проверка (конфликты) — это оценка модели, а не гарантия.
